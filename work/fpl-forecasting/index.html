03 Forecasting · Football data

Predicting the next gameweek, without seeing it.

A Fantasy Premier League points forecast built around one constraint: only use information available before the gameweek being predicted.

Code & evidence ↗

The question

The task is to predict a Fantasy Premier League player’s points in the next gameweek. The central question is chronological: what information could a model actually have known when making that prediction?

The approach

  1. Validate completed, season-tagged gameweek snapshots before feature engineering. Build recent-form and season-to-date features from information available at gameweek t, paired with the target at t+1.
  2. Compare baselines and ridge regression in forward-moving evaluation folds. Each fold trains on earlier target gameweeks and scores the following one, keeping future outcomes out of the features.
  3. Package the workflow as command-line tools with portable model artifacts, DuckDB storage and a read-only local API. Add automated checks and a non-root Docker workflow for repeatable local use.

What came out of it

In the retained ten-window 2024–25 evaluation, ridge regression had the lowest point error among the compared candidates. The repository provides the comparison table, evaluation record, data contract and methodology.

Where the result stops

This covers a defined part of one historical season, not live predictions or a whole-season forecast. The system predicts individual points; it does not optimise squads, transfers, captaincy or budgets. The synthetic example checks the pipeline rather than demonstrating football performance.
